## 已完成验证

- Swift 全量测试：36 项，3 项跳过，0 失败。跳过项为需要环境变量显式启用的媒体/剪贴板真机测试；Android 剪贴板另行启用并通过 1 项真机测试。输出位于本地忽略目录 `build/clipboard-swift-tests.log`、`build/clipboard-android-live.log`。
- Python helper 测试：11 项全部通过，其中剪贴板 8 项、既有媒体 3 项。
- Mac 使用独立命名剪贴板测试文本、URL、空字符串和仅图片；注入适配器测试拒绝访问及失败时保留草稿，不依赖实际触发系统拒绝弹窗。
- Android TCP 模拟端覆盖消息分包、UTF-8 长度边界、写入确认、读回不一致、连接断开、畸形长度、响应超时和辅助进程/转发清理命令。首个文本响应超时有明确提示，不判定为读取成功或空字符串。
- iPhone helper 模拟测试覆盖主表示策略、空字符串、缺少服务后挂载尝试、超时/断线后关闭隧道与下次重新连接、禁止自动重试写入、缺失文本数据时阻止写入及写后核对。
- Release 构建、arm64 产物、ad-hoc 签名验证通过。构建产物为 `build/ScreenTools.app` 和 `build/ScreenTools.dmg`，签名不等同于 Developer ID 公证。
- 界面验证：Tab 位于「手机相册」与「屏幕压暗」之间；Mac 读写与 REDMI 读写成功，iPhone 显示缺失数据错误；错误时保留编辑内容，切换到截图再切回时草稿保留。退出并启动最新产物后草稿为空，自动选择设备正常。默认窗口约 1080 × 750 下布局正常。
- Android 操作后检查 ADB 转发列表和临时服务文件，无本次测试残留；每次操作关闭控制 socket、结束辅助进程并移除端口转发，下次操作重新建立。

## 真机内容保护

- 使用专用测试文字；不在本记录保存用户原剪贴板正文。
- Mac 调试前将完整可读取的剪贴板表示保存在进程内，调试后恢复并获得 `MAC_RESTORE_VERIFIED`。
- Android 真机测试在进程内备份原文本，测试后写回并读回核对；仅承诺恢复文本，不承诺保留 Android 剪贴板原有的非文本表示。
- iPhone 初期空快照探测已恢复并核对。用户随后在手机手动复制普通文字，服务仍不给数据，后续产品写入在预检查阶段被阻止。当前调试脚本会先检查快照中每个声明类型的数据均可完整备份，否则在任何写入前中止。
- 产品不保存正文到文件、偏好设置或日志；编辑草稿只存在于进程内。

## iPhone 当前失败情况

手机已解锁、已配对并开启开发者模式。开发者镜像可用，服务 `com.apple.coredevice.pasteboardservice` 存在。手动复制普通文字后，PULL 返回文本类型，但对应数据描述为 `{}`，没有 bytes；系统 `devicectl device pasteboard` 对照也未得到可用文本。

主要表示策略立即返回但缺失数据；全量解析策略也未解决，在备忘录富文本场景还可能阻塞约 64 秒，故产品保留主要表示策略与超时保护。不能据此确认根因一定是 iOS、DDI 或第三方库中的某一方，也不能推断所有 iPhone 均不可用。

当前界面报告「iPhone 剪贴板服务返回了文本类型，但没有提供文本数据」，保留草稿，写入前中止。即使系统接口确认 SET，也必须读回一致才报告成功。

## 组件与复现

- iOS：`pymobiledevice3==11.26.0`，JSON-lines `clipboard_get` / `clipboard_set`，单次写入最多 1 MiB UTF-8。
- Android：官方 scrcpy-server v5.0.1，SHA-256 `764eb6f79811d5211fe9df341120882ba9994c7a61b897d7bf3fb662e53bc536`。构建时校验并附带 Apache 2.0 许可证，用户无需安装 APK 或 scrcpy。单次写入最多 262130 字节 UTF-8。
- 执行 `swift test`、`python3 -B -m unittest discover -s helper/tests -v`；Android 及 iPhone 显式真机测试方法见 [使用说明](../README.md)。
